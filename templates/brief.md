# 任务书模板（brief.md）

> **为什么是模板而不是代笔**：主代理写任务书只需要**接口**，不需要装下任务细节。
> 字段固定 → 信息量常数级 → 上下文仍然洁净。
>
> 用法：每个子任务一份，落在 `tasks/<id>/brief.md`。子代理**只读这份文件**就能开工。

---

## 必填字段

```markdown
# 任务：<一句话说清要交付什么>

## 目标
<可验收的最终状态。写"什么算做完"，不写"做什么步骤"。>

## 输入
- 路径：<绝对路径或相对仓库根的路径>
- 现状：<一句话说明它现在是什么样>
- 参考：<相关文件 / 文档 / 上次的结论指针>

## 领域能力
<本任务要用哪个 skill / 脚本 / 工具。点名，不要写"按需选择"。>

## 约束
- 可写：<允许改的路径>
- 禁止：<不许碰的路径 / 不许做的动作>
- 风格：<跟随既有约定，或指定>

## 验收条件
<能跑的命令 + 期望输出。写不出命令的，说明为什么。>

## 期望产出
- 产物：<文件路径 + 格式>
- 回报：三行证据（改了什么 / 凭什么说对 / 最不确定的一点）
```

---

## 三条纪律

1. **验收条件必须可执行**。写不出命令 → 说明这个任务还不该派，或验收标准本身要重定。
2. **禁止范围要具体到路径**。"别乱改"不是约束，"不许改 `src/auth/**`"才是。
3. **领域能力必须点名**。写"按需选择"等于没写——子代理不继承你的上下文，它不知道你有什么。

---

## 最小示例

```markdown
# 任务：修复 parseConfig 在空数组时崩溃

## 目标
`parseConfig([])` 返回 `{}` 而不是抛 TypeError。

## 输入
- 路径：`src/config/parse.ts`
- 现状：`parseConfig` 对 `items[0]` 直接取下标，空数组时 undefined 崩

## 领域能力
无（纯代码改动）

## 约束
- 可写：`src/config/parse.ts`、`src/config/parse.test.ts`
- 禁止：`src/config/index.ts`（导出面不许动）

## 验收条件
```
npx vitest run src/config/parse.test.ts
```
期望：全绿，且新增一个空数组用例。

## 期望产出
- 产物：改动后的 `parse.ts` + 测试
- 回报：三行证据
```

---

## 反模式

| 写法 | 为什么不行 |
|---|---|
| "优化一下性能" | 无验收条件，无法判定完成 |
| "参考项目里的写法" | 子代理不继承你的上下文，它不知道你指哪个 |
| "改完告诉我" | 没有三行证据契约，你无法否决 |
| "顺便把 X 也弄了" | 扩大 diff，违反最小改动 |
